## 核心设计：与原版的三个关键区别

| | 原版 | Vue 版 |
|---|---|---|
| 数据模型 | 幻灯片内容是 **HTML 字符串** | **结构化场景图**（`Slide.elements: SlideElement[]`） |
| 编辑器画布 | Reveal.js 同时负责编辑与演示 | Vue 自己渲染画布，Reveal 只用于**演示/导出** |
| 元素操作 | `querySelectorAll` + 直接改 DOM | 响应式状态 + 拖拽时绕过响应式直写 DOM |

第三条是解决「虚拟 DOM 与 Reveal 争夺节点」的关键：**两者不共享 DOM**。

**编辑功能**
- 元素选中、拖拽移动、八向缩放
- **多选**：Ctrl 加选、Ctrl+A 全选、空白处拖动框选
- **组合 / 解组**（Ctrl+G / Ctrl+Shift+G）：点任一成员选中整组，对齐与分布以整组为单位
- **对齐**：左 / 水平居中 / 右 / 顶 / 垂直居中 / 底（单个元素时相对整页）
- **分布**：水平 / 垂直等距（至少 3 个；元素重叠时退化为零间距排开）
- **图层**：置顶 / 上移 / 下移 / 置底
- **吸附**：拖到其它元素边缘、中线或页面中心/边缘 6px 内自动吸附并显示红色参考线

**公式（MathJax 3）**
- 本地 `public/mathjax/tex-svg.js`（约 2MB，离线可用，首次按需加载）
- 用 SVG 输出而非 CHTML：字形以路径内嵌，不需要额外字体文件
- 渲染后按元素框**等比缩放**（MathJax 产出固定尺寸 SVG，改 font-size 无效）；
  缩放上限 1（**只缩小、不放大**）：公式大小由「字号」决定，元素框变大不再把公式撑大，
  避免宽框里的短公式被放大到与正文（26~32px）严重不成比例
- 内置 `\R \N \Z \Q \C \E` 等实数集宏
- 属性面板可直接改 LaTeX；输入与尺寸变化都有防抖，不会每帧重排

**GeoGebra**
- **离线引擎已内嵌**：`public/geogebra/5.0/`（约 97MB，随应用打包），编辑器与演示页都不依赖 CDN
- **打开本地 .ggb**：工具栏「📂 打开 .ggb」一步选文件 → 创建元素并自动加载（base64 内嵌场景图）
- 5 种套件：经典 / 函数绘图 / 几何 / 3D / CAS
- **显示选项**：工具栏 / 代数输入 / 菜单栏 / 重置按钮 / Shift 缩放 / **坐标轴** / **网格**
  （编辑器与演示页一致生效；改动自动重载小程序；旧存档自动补默认值）
- 工具栏 / 代数输入 / 菜单栏 / 重置按钮 / Shift 缩放 均可开关

**演示模式**
- **应用内全屏覆盖层 + iframe**（不再 `window.open`——Tauri 不允许任意新开窗口）
- 演示页资源全部本地化（revealjs / mathjax / geogebra 均从应用 origin 加载，离线可用）
- 资源用 `location.origin` 绝对路径 —— **blob URL 无法解析相对路径**（不是层级 URL）
- Reveal ready / MathJax / GeoGebra 三方加载时序不同步：全部改为**轮询重试**，
  避免「ready 只触发一次而引擎尚未加载完」的竞态
- iframe 内按 ESC 用 `postMessage` 通知宿主退出（跨文档按键不冒泡）

### 第三方命令式库与 Vue 共存的三条经验

1. **宿主元素不能被 `v-if` 条件卸载** —— 一旦卸载，ref 变 null，
   而 Vue 的 DOM 更新是异步的，后续重渲染读到的仍是 null，再也恢复不了。
   错误提示要浮在宿主之上，而不是替换它。
2. **等宿主有实际尺寸再注入** —— GeoGebra 在 0×0 容器里会渲染成空白。
3. **尺寸变化不要重新注入** —— 会丢失作图内容；交给库自己的缩放机制处理。

## 把 Word 文档变成幻灯片（docx → Markdown）

```bash
# 转换（.md 与同名 images/ 目录会生成在 -o 指定的位置）
node tools/docx/docx2md.mjs 讲义.docx -o out/讲义.md

# 可选参数
node tools/docx/docx2md.mjs 试卷.docx --pages 4          # 只输出前 4 页（大文件先切一段预览）
node tools/docx/docx2md.mjs 试卷.docx --group question   # auto(默认) | question | heading | line
node tools/docx/docx2md.mjs 试卷.docx --page-px 900      # 每页像素预算（画布 1080 高，默认 900）
node tools/docx/docx2md.mjs 讲义.docx --wrap 42          # 按字数切行（默认不切，一段一行）

# 端到端验收：把产出交给应用自己的导入器，检查越界/重叠/内容丢失
node tools/docx/verify-import.mjs out/讲义.md
```

然后在应用里打开 **MD 源码面板**（顶栏「MD 源码」），把生成的 .md 粘进去、点应用即可。

**实现**（`tools/docx/`，不依赖任何第三方库，离线可用）：

| 文件 | 作用 |
|---|---|
| `zip.mjs` | 自己解析 zip（docx 就是个 zip），只用到 deflate |
| `xml.mjs` | 极简 OOXML 解析器（属性尊重引号、文本解实体） |
| `omml.mjs` | **Word 公式 OMML → LaTeX**：分式 / 根式 / 上下标 / 括号 / 求和 / 矩阵 / 重音 / 函数名 / Unicode 符号映射 |
| `docx2md.mjs` | 主转换器 + CLI：段落 / 标题 / 表格 / 图片 / 分页 |
| `verify-import.mjs` | 端到端验收：过一遍 `src/composables/mdDeck.ts`，断言不越界、不重叠、不丢内容 |

**踩过的坑（都写进了断言，防止回归）**：

- 相邻公式必须合并成一个 `$…$`：Word 里 `A₁`、`B₁` 常是分开的 OMML，拼出来会得到 `$A_{1}$$B_{1}$`，
  中间那两个美元符会被应用的**显示公式**规则命中，**整行剩下的文字被丢掉**（真题里有 27 行中招）。
  而且 Word 会在相邻公式间插**空 run**，合并时要跳过空文本项。`verify-import.mjs` 里有专门的反向断言。
- 分页要按**像素**而不是行数：应用里一行一个元素框（文本 70+20、混排 120+20、图片 520+20），
  权重口径必须与 `src/types/index.ts` 的 `estimateTextHeight` 一致，否则公式多的页会堆出画布。
- 图片必须独占一行：应用只认行首的 `![]()`。

**已知限制**：文本框 / 浮动对象 / 分栏只按顺序取正文，位置关系丢失；公式若是图片（MathType 截图）不会被识别；
老式 `.doc` 需要先另存为 `.docx`（本机装了 Word，可加一步 COM 转换）。
## 立体几何复刻图形（数学图形 → 复刻图形）

试卷 / 讲义里的立体几何插图基本都是位图：放大就糊，线型改不了，字母也挪不动。
「数学图形」面板第五页签 **复刻图形** 放的是**照着原图量出来**的那几幅常见图，插进页面就是普通数学图形元素，
顶点可拖、边可改虚实 / 粗细 / 颜色、字母可改可拖 —— 相当于把原图"重新画一遍"但保留原样。

**应用内直接转**：页签第一张卡片「＋ 从图片复刻…」选一张线稿，或选中图片元素后用属性面板的「✎ 转成矢量图形」。
弹窗里会叠出识别结果（顶点带序号），**多出来的删、少掉的补**；**顶点字母会自动认出来并填好**，
认得不那么确定的会标黄让人复核，确认后插入即可；选中图片进来时还能直接替换掉原图。
字母默认摆在被抹掉的原字母位置上，所以字母位置跟原图基本重合。
识别器见 `src/composables/vectorize.ts`，字母识别见 `src/composables/glyphOcr.ts`。

弹窗里的编辑动作（**都可撤销**，Ctrl+Z / Ctrl+Shift+Z；拖动按"松开才入栈"合并成一步）：

| 动作 | 怎么做 |
|---|---|
| 顶点偏了 | 按住顶点**直接拖**；也可框选多个一起拖 |
| 多出的顶点 | 点它 → Delete（只连一条线的点会**并到最近的顶点**上，线不会丢）；框选可批量删 |
| 多出的线 | 点它 → Delete（也可以整条线拖着挪） |
| **少了一条线** | 点「＋ 补一条线」→ 依次点两个顶点；**点空白处会先新建一个顶点** |
| 虚实判错 | 点那条线 → 「实线 / 虚线 切换」 |
| 想放大看细节 | 滚轮缩放（「适屏」复位）、中键或「抓手」平移 |
| 题注被一起收进来 | 点「框选识别范围」，拖一个框把图框住，松开自动重识别（会先问一句，因为会丢掉手工修改） |

**回到弹窗继续改**：转好的图形元素上留了识别上下文（原图 + 识别框，`vectorizeCtx`），
选中它后属性面板有「✎ 回到识别弹窗继续编辑」，顶点 / 边 / 字母直接接着改，不用重来。

**识别在后台跑**：二值化之后是纯计算，抽成了无 DOM 的 `vectorizeFromInk` / `vectorizeImageData`，
放进 Web Worker（实测 ~284ms），弹窗打开时界面不再卡住。

| 预设 | 原图 | 顶点 / 边 |
|---|---|---|
| 四棱锥 P-ABCD（PA⊥底面） | 709×476 | 5 / 9 |
| 正方体 ABCD-A₁B₁C₁D₁（含三棱锥） | 655×696 | 8 / 16 |
| 正方体（不标 D₁） | 655×696 | 7 / 13 |
| 正方体 + 空间直角坐标系 | 758×841 | 11 / 16 |
| 四棱锥 P-ABCD + 空间直角坐标系 | 888×659 | 8 / 12 |
| 四棱锥 P-ABCD + 点 O（PO 连线） | 709×584 | 6 / 10 |
| 四棱锥 P-ABCD + 点 O + 坐标系 | 888×683 | 9 / 13 |
| 四棱锥 P-ABCD + 点 C₁ | 778×618 | 7 / 13 |

**怎么量出来的**：这些图是矢量线稿，直接"看"容易差个十几像素。做法是——

1. 先按人眼在带 5% 网格的放大图上把每个顶点位置读个大概（±3% 就够）；
2. 再把每个顶点**吸附到真正的线条交点**：在图上沿每条边采样若干点，统计"附近 3px 内有黑像素"的比例，
   以这个覆盖率之和为目标做坐标下降（多轮，步长 30→15→7→3→1 px，带最短边长约束防止顶点塌到一起）；
3. 用同一套渲染函数把结果叠在原图上比对，残留的偏差继续微调；缺边 / 多边也靠覆盖率一眼看出来
   （某条边覆盖率只有 0.5 就说明那条边不存在）。

最终 8 幅图的**边覆盖率 0.98~0.99**（虚线本身只有 ~0.93 的点覆盖率，所以这就是"贴合"了）。

**坐标轴箭头**：带坐标系的两幅图需要在边的终点画箭头，于是给边样式加了 `arrow` 字段
（`EdgeStyle = { dash, width, color, arrow }`），只作用于那一条边，其余图形不受影响。

**想加新图**：`tools/solidfit/` 里有**自动矢量化**工具 —— 一张线稿进去，顶点 + 边表 + 虚实线出来，
再叠回原图看一眼、按序号填上字母，就能生成可直接粘贴的 `fig(...)` 代码（详见其中的 README）。
拿已经人工核对过的这 8 套当真值实测：**顶点召回 89%、平均误差 1.3%、虚实线判定 100% 对**；
代价是会多出几个落在直线上的冗余顶点，删掉即可 —— 比纯手工量快一个数量级。

## 把 PDF 变成幻灯片（PDF → 可编辑文本 / 每页一张图）

试卷、讲义大多是 PDF，而且**实测下来分两类**：一类有文本层（Word / LaTeX 导出的），一类是扫描件（整页位图）。
入口 `文件 → 导入 PDF（.pdf）`：先探一遍（页数、每页文本块数、图片数），再按情况给默认模式，弹窗里可以改。

| | 抽取文字（可编辑） | 每页一张图（保真） |
|---|---|---|
| 出什么 | 正文 / 标题 / 题号 → 可编辑文本，一题一块 | 一页一张幻灯片，就是整页图 |
| 公式 | **会残** —— PDF 里没有公式结构，分式、根号、上下标会散掉甚至整块丢 | 和原件一模一样 |
| 插图 | **不带过来**（只搬字） | 全都在 |
| 扫描件 | 一个字都提不出来 | 正常 |
| 体积 | 144 页 → 262 KB | 13 页 → 4.3 MB |

手头 6 份样本的实测：长郡期末试题（13 页）、康德三诊（10 页）是**扫描件**；
第56讲（27 页）、立体几何中的复习（144 页）、培优讲义、第51讲（50 页）**有文本层**。
144 页那份抽文本用了 6 秒，出来 274 页幻灯片 / 77151 字。

实现见 `src/pdf/pdfImport.ts`。分页口径（`packPages` / `lineWeight` / `isQuestionStart`）
与 Word 导入**共用同一份**（从 `docxToMarkdown` 引），不然同一个文档换个入口进来分页就不一样。

几个实测踩出来的点：

- **页眉页脚必须剔掉**：讲义每页印书名、试卷每页印"第 557 页 共 1043 页"，不处理的话每张幻灯片头上都挂一遍。
  做法：只拿每页**最上 / 最下两行**当候选，跨页出现 ≥50% 且文本相同（数字归一化后）就判为页眉页脚。
- **题号可能是四位数**：讲义里的题号从 2895 起，而"和上一题差 ≤ 8 才算连续"的判据永远开不了头 ——
  第一版因此题数一直是 0，得允许**第一道题无条件开头**。
- **分栏要拆**：中间有竖缝、两边都有足够内容就左右分别读；混着按 y 排会把左右两栏串成一行。
- **图片模式别一次导太多**：一页就是一张位图，而演示是自动存浏览器本地的（配额只有几 MB，**超了是静默存不上**），
  所以默认只给前 20 页，超过 12 页会提示分批导或用「另存为」存成 JSON。

## 导出 Asymptote 代码（数学图形 → .asy）

选中任意数学图形（复刻图形 / 图片转图形 / 立体几何），属性面板里点 **⌘ 导出 Asymptote 代码**：
弹窗里给出等价的 asy 源码，可复制或存成 .asy 文件。

```asy
size(10cm, 0);
defaultpen(linewidth(1.8pt) + rgb(0.102, 0.102, 0.102) + fontsize(16.11pt));
pen hidden = defaultpen + dashed;      // 被挡住的边

pair P = (2.654, 6.198);   // P
pair A = (2.74, 2.227);    // A
…
draw(P--A, hidden);
draw(P--B);
…
label("$A$", (2.399, 2.306));
```

**为什么是二维**：复刻图本身就是三维立体的一个**投影**，元素里存的只有投影后的二维坐标、没有 z。
要还原成 `A(0,0,0)、B(2,0,0)` 这种空间坐标得靠人判断，程序硬编只会编错 —— 所以老老实实按所见即所得输出 `pair`，
不假装能给你 `import three` 的三维代码。想要三维，拿这份二维图当底稿、把各点抬到三维空间再改。

几何口径与画布渲染（`renderSolid`）**逐条对齐**：同样的边表、同样的虚实、同样的字母落点与夹取规则。
坐标单位是"最长边 = 10"，改整体大小要调 `size(...)`、别改坐标（线宽是按这个尺寸换算的）。

**验证**：装了 Asymptote 就能验，不是纸上谈兵——

- 8 个复刻图预设 + 一张「图片转图形」出来的图，生成的 .asy **全部用 `asy -f svg` 编译通过**（含 LaTeX 字母）；
- 和编辑器里的渲染做**像素比对**（两边都去掉字母只比几何）：
  `asy 画出来的线，编辑器里 100% 都有`（没有多画、画错），编辑器墨迹被复现 90%~99%
  （差的那几个点是虚线间距图案不同：应用是 `6 5`，asy 的 `dashed` 间隙更长）。

小坑：顶点变量直接用字母本身（这样代码好读好改）。若某个字母与 asy 内置常量同名（`N/S/E/W/x/y/z`），
不影响生成代码（全用绝对坐标），但你自己想写 `label(..., N)` 这种方位常量时，把那个顶点变量改个名。

**② 高度自纠被"复制时机"吃掉** ✗（**未修完** ✗）：

    于是页面上仍是 paper-opt-two ✓ → 长选项折行 ✗。
