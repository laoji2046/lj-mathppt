# 三维立体图（geom3d）—— 立项

## 为什么做

现有的数学图形只存**二维**顶点，一条棱该实线还是虚线只能靠**启发式猜**：
沿线段采样墨迹看断不断、凸包内外、虚线样式……实测为了「补出来的线该实该虚」来回试了三版，
其中两版还会伤真值集（配上边 67→65、虚实 62→60）。

立体几何里虚虚实实**是算出来的**：凸多面体的一条棱，只要属于至少一个「正面朝向的面」就是可见的。
有了三维模型 + 面表，下面三类问题在架构上就不存在：

1. **多余顶点**（投影上异面直线假交叉、字母切断线留下的断口顶点）；
2. **虚实判错**；
3. **异面直线在投影上看着相交**（用户那幅棱柱里 D₁A₁ 与 C₁C 就是典型）。

## 现在的状态（v2026.09.1163）

**模块**：`src/composables/geom3d.ts` —— `projectGeom(model, view)`

- 输入：三维顶点 + 面表（+ 辅助线）；视角 azim/elev
- 做：正交投影 → **按面表算每条棱的可见性**（凸体：属于至少一个正面朝向的面即可见）→
  输出跟 `MathFigureElement` 的 `points / mesh / vlabels` **同一套结构**
- 所以**渲染、导出、拖点全部复用现有那条路**，不加新元素类型

**已验证**：拿用户那幅 13 点棱柱（4×3 + P）当靶子，azim -35 / elev 20 ——
立方体被挡的三条棱自动虚线、C₂ 发出的四条辅助线自动虚线，跟原图一致 ✓

## 界面（v2026.09.1163）

面板「图形重建」里多了 **三维立体图…**：粘 JSON → 预览 → 插入到当前页。
弹窗里还能**导入同一张截图、按提示依次点出各顶点 → 反解视角**（截图描点对齐）。

**求解器已自测精确**（合成数据，四种视角）：

    真值 azim -35 elev  20  →  解出 -35.0 /  20.0   残差 0.000%
    真值 azim  35 elev  20  →  解出  35.0 /  20.0   残差 0.000%
    真值 azim -60 elev  12  →  解出 -60.0 /  12.0   残差 0.000%
    真值 azim 120 elev -15  →  解出 120.0 / -15.0   残差 0.000%

**踩过的坑**：`(azim, elev)` 与 `(azim+180, -elev)` 的投影只差一个点镜像、残差一样小，
不夹住缩放符号就会随机挑到镜像解 —— **形状看着对、虚实整个反**。所以拟合里强制 sx>0、sy<0。

**注意**：求解器只解**缩放和平移**，不形状 —— 模型的比例必须跟题目一致。
实测拿一张底面是 1:1.77 矩形的题图去配 2×2 正方形的模型，残差 16%（形状对不上）；
另外**只点 3 个点可能共面**，平面投影本身有二义性，建议至少 4 个点且跨上下两层。

## 踩坑录（2026-09-13 一整天攒的）

这一块最难的地方**不是算法本身，而是"看起来没问题的公式/结构"** —— 出错时它不崩，
只是"差不多在别的地方"：虚实反了、母线差一截、交线跑偏、图形被拉伸。
下面每一条都是先**把手算例子打印出来逐点比对**才定位到的。

### 数学（都是公式看着没毛病）

1. **3D 圆的参数 t ≠ 投影椭圆的参数 θ**（差一个仿射变换）。直接把 t 当椭圆的 a0/a1 用，
   底面虚实会整个反过来、母线也接不上椭圆。做法：切点在 3D 算，投影到 2D 后**换算成椭圆参数**；
   哪半可见由"该点深度是否为正"判定（屏幕点反解回水平面内的 (x,y)，再点乘视线方向）。
2. **弧区间的方向**：写 `[th1, th2]` 时 th2 可能算成 −π（反向），画出来是另一半、虚实照样反。
   要写成"沿正向从 th1 走 fwd"。
3. **椭圆朝向**：用"共轭直径夹角"公式算朝向是错的（半轴长度对、朝向错；球的赤道本该水平却被算成 55°）。
   正解：`MMᵀ` 的特征分解（M = [U V]，椭圆 = M·单位圆）。
4. **圆锥母线 ≠ 圆柱母线**：圆柱母线是竖线、落点就是椭圆的左右端点；
   圆锥母线是**从顶点向底面圆作的切线**，落点在切点上（比左右端点更靠外）。混用会让母线穿进底面。
5. **Cramer 法则替换的是「列」不是「行」** —— 按行传参，两平面交线的基点解到别处去了。
6. **两直线求交的 s 符号**：t 对、s 反，结果全被 `s ∈ [0,1]` 滤掉，交线一条都出不来。
7. **共面退化**：拿同一个面的三点作平面时（平面与那个面重合），逐面求交会得到"整面重合"的退化段、
   接不成环，截面会悄没声地消失。要特判：平面与某面重合就直接拿那个面当截面。
8. **静态 view 与 viewOf 的纵横比必须一致**（圆锥曲线那边）：元素框是按静态 view 给的，
   不一致图形会被拉伸 —— 自定义抛物线就中招过。

### 结构 / 工程

9. **缩进是骗人的**：靠缩进判断 Vue 模板的嵌套会翻车（多次插入新块时照抄了锚点处的缩进）。
   要用 `<div>/</div>` 计数判定结构。
10. **顺序陷阱**：截面/交线会往 `faces` 里塞"只存在于 points 里的新点"，而 `inside()` 遍历 faces 去索引 `P3`
    —— 把垂线计算放在截面之后就会索引越界崩溃，而且**只在"同时有截面和投影"时才炸**。
11. **Windows `ReplaceFileW EIO` 报错 ≠ 没改成功**：改动可能已生效，直接重做会插重复块。报错后先 `grep` 确认。
12. **Vite 模块缓存**（一天踩 3 次）：新加的导出在浏览器里死活不生效，但 node 侧用当场打包的 bundle 是对的。
    **判断法：node 对、浏览器不对 = 缓存**，`npm run dev -- --force` 重启。
13. **取名冲突静默覆盖**：`nextMarkName()` 只查 vertices/marks，不知道 lineMeets/meetPoints/projectPoints
    里已用掉的字母 —— 新点重名后按名字去重，把旧点顶掉了。取名要把所有"点来源"都算上。

### 可复用的手算例子（拿来做回归最省事）

- 正方体 A(0,0,0) B(2,0,0) C(2,2,0) D(0,2,0) A₁…D₁：
  - `A₁C ∩ 平面 AB₁D₁ = (2/3, 2/3, 4/3)`；
  - `AC ∩ BD = (1,1,0)`；
  - 平面 `AB₁D₁`(z=x+y) ∩ 平面 `A₁BD`(x+y+z=2) 的交线是 `z=1、x+y=1`，即 `(0,1,1)–(1,0,1)`；
  - `A₁` 在底面 ABC 上的射影就是 A(0,0,0)；`B` 在平面 AB₁D₁ 上的射影是 (4/3, −2/3, 2/3)。
- 虚实判定的核心：凸多面体一条棱，只要属于**至少一个正面朝向的面**就可见。
