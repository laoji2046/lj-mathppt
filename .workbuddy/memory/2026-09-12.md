## 11:30 关键修复（版本 2026.09.1109）

- **「拖动放大后混排内容被截断」的真凶：`transform-origin` 与 flex 对齐不一致。**
  混排宿主是 `justify-content: flex-start`（align=left 时），内容贴左边缘；
  而缩放写的是 `transform-origin: center center` → 放大后有一半跑到左边框外，被 `overflow: hidden` 裁掉。
  现象特征：**左边被切、右边完好** —— 我当时没细看方向，误判成测量问题，白改两轮。
  修法：原点跟随对齐 —— `transformOrigin = (align === 'left' ? 'left' : align === 'right' ? 'right' : 'center') + ' center'`；
  导出侧给 `.fx-mixed` 写 `data-align`，`fitMixed` 读它取原点，保证 PDF/PNG/放映与画布一致。
- **教训：先看裁切方向**。左右被裁 → 对齐/缩放原点问题；上下被裁 → 高度测量/换行问题。
- 保留的加固（针对 MathJax 溢出父盒却不撑大父盒）：真实占位 `max(offset, scroll)`、按绘制范围并集兜底、
  渲染后 rAF + 120/420ms 复量、`ResizeObserver` 同时盯内容节点。
- `fitMode`（fill/shrink）与 `autoBox`（插入时外框贴合内容）是自由缩放的基础：**空有大框 + fill 就是 1101 "公式过大"的成因**。
- 构建坑：`dist/assets` 会堆历史产物（曾 157 个 / 87 MB，Tauri 把整个 dist 打进 exe → 58 MB），
  已加 `clean-dist.cjs` 并在 README 构建步骤注明；exe 降到 30 MB。

### 坑（血泪）：不要用 PowerShell 改含中文的源码文件
- `Get-Content -Raw` + `Set-Content -Encoding UTF8`（Windows PowerShell 5.1）会**按 GBK 解码 UTF-8 文件**再写回 → 整个文件中文变乱码、
  更糟的是 GBK 双字节会把后面的 ASCII 引号**吞掉**，导致字符串未闭合（本次直接损坏 pptLayouts.ts，17 处）。
- 抢救办法（已成功）：按 `[Text.Encoding]::GetEncoding('GBK').GetBytes(乱码文本)` 还原原始 UTF-8 字节再 `UTF8.GetString` 解码回来；
  但被替换成 `?` 的少数字符不可逆 —— 之后按行扫描「引号不成对 / 含 U+FFFD」逐处补齐即可。
- **正确做法**：一律用 edit / write 工具改文件；需要批量替换时写 node 脚本（`fs.readFileSync(p, 'utf8')` / `writeFileSync(p, s, 'utf8')`）。

### 18:20 修「导出 PDF 公式行重复」（版本 2026.09.1116）

- **现象**：画布正常，导出 PDF 时混排里公式的**第 2、3 行各渲染两遍**、撑出框被裁。用户给的截图里特征很关键：**只有后两行重复**。
- **根因（读 vendored MathJax 源码确认，不是猜的）**：`MathJax.typesetPromise` 的实现是
  `document.options.elements = e; document.reset(); return handleRetriesFor(() => document.render())` ——
  **既不串行化也不排队**。而 PDF 导出路径对同一页 prepare 了两次：`Reveal.on('ready')` 先 prepare 当前页，
  紧接着 `prepareAllForPrint()` 又把所有页（含当前页）prepare 一遍。第一次渲染没跑完，第二次 `reset()` 后重扫 DOM：
  第 1 行已变成 mjx-container 扫不到了，**还是 `\(...\)` 原文的第 2、3 行被渲染第二遍** → 与现象完全对上。
- 画布侧 `MathElement.vue` / `RichTextElement.vue` 早有 `rendering`/`pending` 串行化保护（前者的注释就写着「避免把多个 mjx-container 叠进同一个宿主」），
  **导出路径一直漏着** —— 同类问题要三处一起想：画布、导出/放映、缩略图。
- 修法：导出引导脚本收敛成单入口 `pumpMath()`（全局唯一 typesetPromise 调用）+ 串行化 + 去重（**排队中与正在排的都要查**）
  + 不再用 `typesetPromise(undefined)`（重排整篇文档，最危险的一次 reset）+ 打印就绪等 `mathBusy`。
- **方法学收获**：把生成的引导脚本原文抠出来、用 `new Function(...)` 加桩在 node 里**直接跑真实代码**，比只做字符串断言强得多 ——
  第一版修复只查待排队列、漏了在排批次，就是被这个测试当场抓出来的。
  同时注意**测试自身的保真度**：我一开始用 `mk('A')` 造了两个不同对象去模拟「同一页 prepare 两次」，
  而真实路径传的是同一个 section 节点，导致测试假失败 —— 测试要复刻真实调用形态，否则会误导。
- 另一个小坑：`Select-String` 对 2MB 单行文件（`tex-svg.js`）计数不可靠（返回 0），要改用 node 读文件统计。

### 17:20 修导出/放映公式定界符 + Markdown 导入改混排（版本 2026.09.1114）

- **真 bug（比我一开始说的更严重）**：导出/放映侧 MathJax 配置只声明了 `displayMath: [['$$','$$']]`，
  而画布侧是 `[['$$','$$'], ['\\[','\\]']]` —— 混排里的 `$$...$$` 会被 `normalizeMixed` 归一成 `\\[...\]`，
  于是**用户在混排面板用「多行显示」写的公式，放映和导出时显示成字面文本**。
  教训：`normalizeMixed` 是一种内部表示，它的输出必须与**每个**消费端的 MathJax 配置对齐 —— 画布 / 导出 / 缩略图各有各的配置，最容易漏。
- 顺带把公式元素在导出侧从 `\\(...\)` 改成 `\\[...\]`：画布用的是 `tex2svg(..., { display: true })`，导出侧用内联是历史遗留，
  同一份课件画布上 `\\frac` 是 display 排版、导出后变 textstyle。
- Markdown 导入的 `$$...$$` 改成混排元素（`$\\displaystyle ...$`）；反向导出把「单独一行的展示公式」还原成 `$$...$$`，往返幂等。
- **测试脚本的转义教训**：在 run_code 里拼 JS 测试脚本时，反斜杠要穿过「我写的字符串 → 生成的文件 → 文件里的 JS 字符串 → 实际值」四层，
  手写 `\\\\\\\\[` 这种极容易错（本次第一版就写错了，报出一个假 FAIL，白查一轮）。
  **正确做法：模板里用占位符 `@@B@@` 代表一个反斜杠，最后 `.split('@@B@@').join(String.fromCharCode(92))`** —— 可读且不会错。
