## 三、踩坑记录（省下次的力气）

1. **Vite 只"新增" `public/` 的文件 ✗，不删已移除的** ✓ ——
   移走目录后直接 `npm run build` 体积**不变** ✓，必须**先删 `dist` 再建** ✓ 才看得到真实体积 ✓。
2. **`defineAsyncComponent` 对"常驻挂载（无 v-if）"的组件无效** ✗ —— 它一渲染就立刻拉 chunk ✓。
   本次 `App.vue` 里 7 个对话框都有 `v-if` 门控 ✓ 才改造 ✓；`LayoutGallery` 被常驻挂载 ✓，
   改造后只省了 2 KB ✓（聊胜于无 ✓）。改造前**必须先看模板有没有 `v-if`** ✓。
3. **懒加载必须实测点击** ✗ —— 构建通过 ≠ 点得开 ✓。
   本次用 CDP 点「模板库」 ✓，观察到新增模块请求 `TemplatePicker.vue` ✓ 且弹窗完整渲染 ✓ 才算过 ✓。

## 五、更远的（第 3 层：真插件化）

**可行性** ✓（Vite 的 chunk + Tauri 的本地加载天然支持 ✓），**但有真正的设计难点** ✗：

```
共享内核：types/index.ts 61 KB + stores/deck.ts 38 KB + reveal/renderer.ts 73 KB
```

**任何插件都要依赖内核** ✓，而**内核不能反过来依赖插件** ✓ —— 所以边界只能是"**叶子功能**"：

- ✅ 适合做插件：导入导出（pptx/docx/pdf）✓、编辑器（矢量描摹/3D/几何画板）✓、运行时（GeoGebra/Desmos）✓
- ❌ 不适合：**新增元素类型** ✗ —— 它必须**同时注册进导出渲染器** ✓，那需要一套插件 API（注册点 ✓），是另外一大步 ✓
