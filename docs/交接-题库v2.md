## 3. 真机探针怎么做（双验证的「真机」那一半）

- **隔离**：`$env:APPDATA = 临时目录`，先把线上 `library.db` **复制**进去（Rust 的 `library_path()` 读的是 APPDATA 环境变量 ✓），
  起 exe 时设 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=NNNN` + `WEBVIEW2_USER_DATA_FOLDER=<临时目录>`
- **收尾必查**：线上库 **sha256 前后一致**（证明全程只动副本 ✓）
- **期望值一律从副本现算**（用 `node:sqlite` 读副本/源 meta），不要写死数字 —— 题量一变就会假绿 ✗
- 现成例子：`.probe/v1440m1.cjs`（M1，28/28）、`.probe/v1441m2.cjs` + 页面脚本 `.probe/_page1441.js`（M2，43/43）
- ⚠ **exe 一启动、宿主 pwsh 一退出，应用会跟着死** → 要么「起应用 + 跑探针 + 关应用」在**同一条命令**里跑完，
  要么用后台任务（`run_in_background` + 长 sleep）撑着
- ⚠ 受限沙箱下 **WebView2 的 CDP 起不来**（命名管道被拦，实测「CDP 未就绪」）→ 真机探针要在更宽的模式下跑
- `$env:DS_KEY` 只在探针里用（AI 真实调用），**绝不写进任何源码/文档** ✓

**现在的两道闸门（v1443 起）**：

1. 批量删除 **超过 20 道**必须**手输题数**才执行（`window.prompt`，对不上就取消）；
2. Rust `lib_q_batch` **删除前自动整库备份** → `library.db.bak-qdel-<时间戳>`（同目录，4MB 拷贝），界面提示「删除前已自动备份整库」。

**以后动 `lib_*` 的规矩**：

- 任何**破坏性**操作（删除 / 清空 / 迁移）都先自动留一份整库备份，并在返回值里带上备份路径；
- 探针只用**副本**（临时 `APPDATA`），跑完必须核对线上库 sha256 **未变**；
- `_backup/library/` 里的库快照**不要清理** —— 那是真出事时的最后一道保险。

**另一个教训（写文档）**：`String.replace(anchor, anchor + 新内容)` 的替换串里 `` $` `` = 「匹配前的全部内容」，
