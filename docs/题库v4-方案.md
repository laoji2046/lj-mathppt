## 1. 先立六条原则

1. **数据优先且可直接访问**：题目内容永远能从 `library.db` 或导出的 JSON / Markdown 里拿出来，不被单一界面锁死。
2. **自动化不能用猜测掩盖歧义**：AI / OCR 拿不准就标 `needs_review`，**绝不猜完直接入库**。
3. **第三方调用由用户主动触发**：MinerU / LLM 必须点了才调，用用户自己的 Key（沿用现状）。
4. **一份真相**：画布 / 缩略图 / 演示 / 导出 / 预览共用同一套渲染与结构规则（沿用 `ENGINEERING-NOTES §一`）。
5. **破坏性操作先备份**：删除 / 清空 / 迁移前自动留整库快照（v1443 已落地，继续扩大）。
6. **升级只覆盖程序**：`library.db`、图片、Key、配置、任务状态不在升级范围内。

> 来源：QuizForge `docs/PRODUCT.md` 的五项全板块共同原则 + 我们自己的 §一 纪律。

## 2. 数据模型 v4（SQLite 迁移）　优先级 P0

### 2.1 DDL 草案（v3 → v4，幂等 + 先备份）

```sql
-- A. 题目生命周期 / 编号 / 主观难度 / 来源分类 / 告警
ALTER TABLE library_item ADD COLUMN code                  TEXT;     -- 可读稳定编号 P-2026-0001（仅 question）
ALTER TABLE library_item ADD COLUMN status                TEXT;     -- draft/needs_review/ready/approved/published/rejected
ALTER TABLE library_item ADD COLUMN source_kind           TEXT;     -- 校内/高考真题/模拟/联考/专题汇编/教辅/未知
-- （主观难度 subjective_difficulty：2026-09-19 拍板不做，见 §11）
ALTER TABLE library_item ADD COLUMN warn                  TEXT;     -- 抽取告警（AI warnings）
ALTER TABLE library_item ADD COLUMN sha256                TEXT;     -- type=asset 行：内容摘要
ALTER TABLE library_item ADD COLUMN batch_id              TEXT;     -- 来自哪一批导入（题目继承批次来源）
CREATE INDEX IF NOT EXISTS ix_q_code        ON library_item(code);
CREATE INDEX IF NOT EXISTS ix_q_status      ON library_item(type, status);
CREATE INDEX IF NOT EXISTS ix_q_source_kind ON library_item(type, source_kind);
CREATE INDEX IF NOT EXISTS ix_asset_sha     ON library_item(type, sha256);

-- B. 编号计数器（年度序号）
CREATE TABLE IF NOT EXISTS question_code_counter (
  year   INTEGER PRIMARY KEY,
  serial INTEGER NOT NULL DEFAULT 0
);

-- C. 修订快照（对齐 deck 已有的版本历史）
CREATE TABLE IF NOT EXISTS question_revision (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  qid        INTEGER NOT NULL,
  version    INTEGER NOT NULL,
  snapshot   TEXT    NOT NULL,   -- 整条 meta 的 JSON 快照
  reason     TEXT,               -- patch / import / batch / ai / restore
  created_at TEXT    NOT NULL,
  UNIQUE(qid, version)
);
CREATE INDEX IF NOT EXISTS ix_rev_qid ON question_revision(qid, version DESC);

-- D. 导入批次 + 草稿（AI/OCR 输出先落这里）
CREATE TABLE IF NOT EXISTS import_batch (
  id             TEXT PRIMARY KEY,
  source_type    TEXT,            -- pdf_paper / pdf_book / pdf_topic / md / json / manual
  source_path    TEXT,
  source_label   TEXT,
  summary        TEXT,
  question_count INTEGER NOT NULL DEFAULT 0,
  status         TEXT,            -- running / done / failed / partial
  idem_key       TEXT,            -- 幂等键（同一文件 + 同一策略不重复计费）
  extra          TEXT,            -- 解析器版本 / 页数 / 策略
  created_at     TEXT NOT NULL,
  finished_at    TEXT
);
CREATE UNIQUE INDEX IF NOT EXISTS ix_batch_idem ON import_batch(idem_key) WHERE idem_key IS NOT NULL;

CREATE TABLE IF NOT EXISTS import_draft (
  id            TEXT PRIMARY KEY,
  batch_id      TEXT,
  source_item_id TEXT,            -- page_12_q_03
  source_label  TEXT,             -- 例如：第12页 第3题
  page          INTEGER,
  bbox          TEXT,             -- 原图坐标（MinerU 已经给了，别再丢）
  confidence    REAL,
  needs_review  INTEGER NOT NULL DEFAULT 1,
  stem TEXT, options TEXT, answer TEXT, solution TEXT,
  qtype TEXT, section TEXT, difficulty INTEGER, knowledge TEXT,
  year INTEGER, paper TEXT, source_kind TEXT,
  raw_text      TEXT,             -- 版面解析原文（人工修的底稿）
  warn          TEXT,
  status        TEXT NOT NULL DEFAULT 'needs_review',  -- 见 §5.1
  target_qid    INTEGER,          -- 更新已有题时填
  extra         TEXT,
  created_at    TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS ix_draft_batch ON import_draft(batch_id, status);

-- E. 资产引用表（图库仍是 library_item(type=asset)，这里只加显式引用）
CREATE TABLE IF NOT EXISTS question_asset_link (
  qid        INTEGER NOT NULL,
  asset_id   INTEGER NOT NULL,
  role       TEXT,               -- problem_image / solution_image / source_crop
  sort_order INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY (qid, asset_id)
);

-- F. 知识点/方法受控词表
CREATE TABLE IF NOT EXISTS kp_catalog (
  kp      TEXT PRIMARY KEY,       -- 规范名
  kind    TEXT NOT NULL,          -- knowledge / method
  aliases TEXT,                   -- 逗号分隔别名
  parent  TEXT,                   -- 板块/章节前缀（层级靠它，不靠平铺 422 条）
  status  TEXT NOT NULL DEFAULT 'published'
);
```

### 2.2 逐字段说明与来源

| 字段 | 含义 | 来源 | 优先级 |
|---|---|---|---|
| `code` + `question_code_counter` | 人可读稳定编号 `P-2026-0001`，老师能口头引用 | Sitimo | P0 |
| `status` | 题目生命周期（见 §5.1） | ECNUQuizHub / QuizForge / MathCyclus | P0 |
| `source_kind` | 来源类别（六类规约，见 §3） | xiaochen | P0 |
| `warn` | 抽取告警随题走 | Teacher-DB 的 warnings | P0 |
| ~~subjective_difficulty~~ | 0-10 主观难度 | Sitimo | **已拍板不做**（见 §11） |
| `sha256` / `question_asset_link` | 内容寻址复用 + 显式引用 | QuizForge | P2 |
| `batch_id` | 题目继承批次级来源，不必每题重填 | Teacher-DB 的 documents 级来源 | P1 |
| `import_batch` / `import_draft` | 批次 + 草稿（含 `page` / `bbox` / `confidence`） | MathCyclus + Teacher-DB | P1 |
| `question_revision` | 修订快照（对齐 deck 的版本历史） | Sitimo / MathCyclus | P1 |
| `kp_catalog` | 受控词表（canonical → aliases） | xiaochen + Teacher-DB | P0 |

### 2.3 迁移纪律

- `lib_migrate` 增加 v4 步：`lib_backup_before(4)` → 幂等 DDL（先查 `pragma_table_info` / `sqlite_master`）→ 回填 → 写 `schema_version = 4`。
- **回填规则**：旧题 `status = published`（169 道行为完全不变）；`source_kind` 由 `paper` / `year` 现算；`code` 按 `year` 逆序分配。
- **防降级**：程序只接受 `schema_version <= LIB_SCHEMA_VERSION`，高于自己则拒绝打开（来源 QuizForge / Teacher-DB）。
- 迁移后 `lib_health` 必须报 0 违规（含新增字段的空值统计）。

### 2.4 向后兼容

- `meta` 仍是**全量真相**，真列只是索引 + 约束；`lib_sync_qcols` 继续做单向同步（自 v3 起的三处共用入口不变）。
- 新增字段一律允许为空；老存档（deck JSON / 导出的题库 JSON）不因缺字段而拒收。
- 导出格式加 `version: 2` 并保留 `questions[]` 兼容读法（`parseQuestionsJson` 已容忍三种写法，继续扩）。

## 3. 来源规约 `source_normalize`　优先级 P0　⭐⭐⭐

直接借 xiaochen-math-treasure `mathbank/source_normalize.py` 的完整做法
（它把 1312 题 95 种来源规整到 88 种，**合规率 36% → 100%**）：

**六类命名模板 + 空值兜底**

| 类别 | 模板 |
|---|---|
| 校内考试 | `{学段} · {考试类型} · {学校} · {学年}` |
| 高考真题 | `{年份} · {卷种} · 高考真题` |
| 模拟 | `{年份} · {地区} · 模拟` |
| 联考 | `{年份} · {考试名} · 联考` |
| 专题汇编 | `高考 · 专题汇编 · {专题}` |
| 教辅自编 | `教辅 · {名称}` |
| 空值 | `未知` |

**分隔符 ` · `（两侧带空格）**，但**高考真题是唯一例外**：历史裸写式原样返回，否则同一份卷会裂成两条来源。

**两层归一**
- **Tier 1 精确别名表**：覆盖库内已出现过的全部取值 + 原始文件名 / 裸写式 → 直接返回规范写法（最可靠）。
- **Tier 2 结构兜底**：剥离文件名噪声尾缀 → 归一分隔符 → 归一卷种罗马数字（I/II/III → Ⅰ/Ⅱ/Ⅲ）→ 应用学校别名。

**三条防护**
1. **合规正则** `_SOURCE_PATTERNS` + `is_canonical_source()`：既用于批量报告残留，也用于归一的**幂等保护**（已合规原样返回）。
2. **LaTeX 幻觉拦截**：AI 拿不准时会把 `\begin{tikzpicture}` 塞进 `source`，命中即判无效来源。
3. **校本条目不入库**：本校映射与学校别名从 `data/source_canonical_map.json`（gitignore）或 `~/.config/...` 运行时加载，
   缺失 / 坏 JSON **静默回退**到内置通用规则——不阻断入库，开源仓也不泄露学校名。

**落库实时钩子**：`lib_save` / `lib_save_many` / `lib_q_patch` / `lib_q_batch` / 导入 五处写 `paper` 前调用 `normalize_source()`，
与「事后批量归一」共用同一函数（单一事实源，绝不出现第二套口径）。

**实现位置**：Rust `src-tauri/src/source_normalize.rs`（权威）；TS 侧 `useQuestionImport.ts` 只做**预览展示**，不改写。

**验收**：169 道逐条复核 → 生成《来源归一报告》（合规率、残留清单）；新导入来源 100% 合规。

## 4. 知识点 / 方法体系　优先级 P0–P1　⭐⭐⭐

**模型**：`canonical → aliases[]`，**落库即归一**（`函数的单调性` 自动折叠成 `函数单调性`），从源头杜绝碎片化。

**上下文化预设**（借 Teacher-DB `lib/education-taxonomy.ts`）：预设随「学段 + 板块」变化。
我们只做数学，简化为 **学段（初中 / 高中）× 我们 11 个板块**；地区 / 教材版本暂不做（以后要加就加 `地区·X` / `教材·X` 两个前缀）。

**首版按「板块级」落地**（2026-09-19 拍板）：只入库我们的 11 个板块（`kind='knowledge'`, `parent='高中'`）+ 约 30 个方法；
初中那 15 个先不做，避免仓库里躺着用不上的空标签（见 §11）。

**参考骨架**（Teacher-DB 的 mathTags，作为将来收到的考点级底稿）

- **高中 12 个**：集合与逻辑 · 函数性质 · 指数对数 · 三角函数 · 平面向量 · 数列 · 立体几何 · 解析几何 · 概率统计 · 导数 · 复数 · 计数原理
- **初中 15 个**：实数 · 整式与分式 · 一次方程与不等式 · 二次方程 · 一次函数 · 反比例函数 · 二次函数 · 三角形 · 四边形 · 圆 · 相似 · 锐角三角比 · 统计 · 概率 · 几何证明
- **方法 30 个起步**（从 xiaochen `solve_method` 70 个里挑）：定义法 · 分类讨论 · 数形结合 · 换元法 · 待定系数法 · 分离参数法 · 构造函数 · 基本不等式法 · 韦达定理 · 配方法 · 消元法 · 坐标法 · 向量法 · 空间向量法 · 等价转化 · 放缩法 · 数学建模 · 特殊值法 · 排除法 · 综合法 · 分析法 · 反证法 · 裂项相消法 · 错位相减法 · 数学归纳法 · 分类计数原理 · 古典概型计算 · 导数法 · 定义域优先 · 端点与无穷检查

**治理规则（关键——避免重蹈 xiaochen 422 条粒度重叠的覆辙）**
1. 一个规范名只表达**一个可判定考点**，不许出现 `集合的交集` / `集合的交集运算` / `集合的交集、并集、补集` 并存；
2. **层级靠 `parent` 前缀**（板块 / 章节 / 考点），不靠平铺几百条；
3. **别名必填**：新增规范名必须至少给一个别名，否则归一形同虚设（xiaochen 422 条只配了 64 个别名，覆盖率过低）；
4. 定期合并同义 / 包含关系，并在 `kp_catalog.status` 标记 `merged` / `deprecated` 而不是直接删（老数据仍可读）。

**验收**：录入时能挂知识点 / 方法；题库能按知识点 / 方法**多选筛选**；旧 169 道支持批量补。

## 5. 录入加固　优先级 P1　⭐⭐⭐

### 5.1 生命周期状态机

```
draft ──→ needs_review ──→ ready ──→ approved ──→ published
   │            │            │
   └────────────┴────────────┴──→ rejected（明确不入库，保留审计）
                └────────────────→ blocked（缺题干 / 更新目标不存在，必须人工修）
```

- **只有 `ready` / `approved` / `published` 能进正式库**；`needs_review` / `blocked` 绝不自动写入。
- 来源：ECNUQuizHub 的三态 + MathCyclus 五态 + QuizForge 的「不会悄悄猜测后直接写入题库」。

### 5.2 批次与草稿

- `import_batch` 记一次导入 / 识别（来源类型、路径、题数、状态、幂等键、extra）。
- `import_draft` 承接 AI / OCR 输出，**带 `page` / `bbox` / `confidence` / `needs_review` / `raw_text`**；
  人工确认后才写 `library_item`（同时写 `question_revision` 与 `import_batch.question_count`）。
- 这一步同时补上我们**丢掉的 MinerU 坐标**（`contentJson` 里本来就有 bbox）。

### 5.3 抽取质量闸门（把 QuizForge 的原则落成代码）

1. **OCR 后端 / 拆题方式 / 题号边界三者正交**——不互相污染配置。
2. **机械切块先固定题数，AI 不得增减**；数量不符 → **整组转人工**，不合并、不猜。
3. 题号连续性检查；**跳号 / 乱序 / 重复号保持原序**，但必须过下面的闸门。
4. 闸门清单：`空题干` / `0 选项（选择题）` / `乱码比例` / `孤儿解析` / `图片缺失` / `内容守恒`（切出字数与原文量级比对）。
5. 任一闸门失败 → `needs_review`，**保留 `raw_text`** 供人工在草稿里改。

### 5.4 幂等 · 重试 · 成本纪律

- 抽取任务带 `idempotencyKey`（**同一份 PDF + 同一策略不重复计费**）。
- **识别历史**：原文件 + 最终 Markdown 归档；**重转产生新记录、不覆盖旧结果**；
  **从历史重建只建立待审核任务，不调 OCR / LLM**（这条直接省钱）。
- 任务重启**不自动重放在途请求**；失败要「明确重试」而不是悄悄重跑。
- 来源：Teacher-DB 的 `extraction_runs`（`idempotencyKey` UNIQUE + `attempt` + `nextAttemptAt` + 租约）+ QuizForge 的成本纪律。

### 5.5 来源与告警随题走

- `warn`（AI warnings）落 `library_item.warn`，界面题卡显示角标。
- `source_kind` + `paper` / `year` 从批次继承（§2 的 `batch_id`）。

### 5.6 探针验收（`.probe/v14xx-import.cjs`）

| # | 断言 |
|---|---|
| 1 | 同一份 PDF 二次导入 → OCR 调用数 0（幂等命中） |
| 2 | 机械切块数量与 AI 返回数量不符 → 整组 `needs_review`，正式库题数不变 |
| 3 | 制造 0 选项 / 空题干 → 对应草稿 `needs_review`，`warn` 有值 |
| 4 | 从识别历史重建 → 不触发 OCR，只生成草稿 |
| 5 | 幂等键重复 → 第二次被拒（409 语义） |
| 6 | 草稿未确认 → `library_item` 数量不变 |
| 7 | 线上库 sha256 全程未变（沿用纪律） |

## 6. 资产治理　优先级 P2　⭐⭐

现状：`type=asset` 行 + `meta.src`，前端 `useAssets.ts` 缓存。

补齐（来源 QuizForge）：
- 资产行加 **`sha256` 内容摘要** → **同内容复用、同名异内容拒绝覆盖**；
- `question_asset_link` 显式引用（现在靠 `meta.images`，跨机迁移时容易丢关系）；
- 题目软删**保留**图片；
- **永久清理必须跨「正式库 + 版本历史 + 试卷/讲义引用」确认无引用**；任一来源不可读就 **fail-closed**；
- 清理前后**二次扫描**并比对大小 / mtime（期间变化的一律不删）。

## 7. 组卷（M4 剩下的那半）　优先级 P2　⭐⭐⭐

借 xiaochen-math-treasure 的完整设计：

**细目表组卷**：每行 = `考点 + 题型 + 难度 + 解法 + 题量`；考点支持多值（逗号分隔，OR 匹配）；

**试卷模板**：内置（周测 100 / 月考 150 / 随堂练 50）+ **个人预设**（存本地库，重装不丢）；

**分值**：逐题改 + **批量设分**（按题型）；留白（标准 / 紧凑 / 无）。

**导出**：保存试卷（历史试卷库可载入二次编辑）/ PDF / Word / TeX（沿用现有导出链，不另写渲染）。

**导出优先级**（2026-09-19 拍板）：**先做 PDF 试卷**；A4 讲义与 Word 排其后。

**另加：导出为 Markdown 题库**（拍板要做）——把 DB 反向导出成 `题库/<来源>/<编号>.md`（一题一文件，frontmatter 带
`id` / `code` / 来源 / 知识点 / 难度 / `status`），可用 Obsidian 打开；既是「数据不被锁死」的出口，也是一份可 git 的备份。

## 13. 修复记录（v1445 · 校对表公式显示 + excerptOf 的 $$…$$ bug）

> 起因：用户截图反馈「右侧题目中题干只剩文字，公式信息消失」。

### 13.1 根因（一个是 bug、一个是设计错位）

1. **设计错位**：校对表卡片用的是 `excerptOf()` —— 那是**列表「扫一眼」用的摘要函数，按设计把 `$…$` 整个剥掉**。
   可校对的场景里**公式正是要核对的内容**，剥掉等于让人没法校对 ✗。
2. **真 bug**：`excerptOf` 先执行 `\$[^$]*\$`。遇到**块级 `$$…$$`** 时会**把 `$$` 两两吃掉**，
   公式内部的 `\left` `\frac` 等命令残留下来、再被下一条规则部分剥掉 → 卡片上只剩 `\;` `\\` 这种噪声 ✗。

（**数据没丢**：库里题干一直是完整的 `$…$` 原样。）

### 13.2 改法

- 新增 `stemPreviewText(raw, n)`：**保留公式**，只折叠空白 + 截断（列表摘要仍用 `excerptOf`，两者用途分开）；
- `QuestionImportDialog` 卡片改为 `renderCardStems()`：① 先落**纯文本**（`$…$` 原样可见，MathJax 失败也不空白）；
  ② 再交给 `typesetHosts()`（**只排版、不写内容**）**一次排一批**；超过 120 张卡就不跑 MathJax；
  ⚠ 内容由函数写，模板里不再绑 `{{ }}` —— 否则任意响应式变化都会把渲染结果冲掉；
- `excerptOf` 修顺序：**先剥 `$$…$$`**，再剥 `$…$` / `\[…\]` / `\(…\)`，最后清残留反斜杠与花括号。

### 13.3 验证（`.probe/v1445fix.cjs`，**22/22 全绿**）

- 校对表卡片里 **7 个 MathJax 节点**（公式**真的渲染出来了**）✓；卡片纯文本仍含正文（不是空白）✓
- 卡片里**反斜杠噪声 0** ✓；题库面板列表摘要也干净（`excerptOf` 修复）✓
- 库里题干**仍含公式源码**（`\mathbf` / `\sin C`）→ **数据没丢** ✓；线上库 sha256 未变 ✓

### 14.4 三个工程教训（下次别再踩）

1. **算出来的值要检查是否真进了 `serde_json::json!({...})` 的键里**（`lib_source_report` 的 `byKind` 就是这么丢的）：变量被算但没被用，Rust **只给 warning** —— 编译过、单测过、界面也不报错，只是**报告少一块**。
2. **`Get-Content` 在这份 `lib.rs` 上报的行号是错的**：文件是 UTF-8，而 PS 5.1 默认按 GBK 解码，中文后面的换行字节被当 GBK 尾字节吃掉 → 报 2504 行而真实 2679 行，`fn` / `cargo` 的行号全偏移（照着改就会改错地方）。
   要按行号定位**一律用 `node` 或 read 工具**（`fs.readFileSync` 后按 LF 切分），别用 `Get-Content`。
3. **同一个坑会让 `.ps1` 里的中文注释吃掉下一行** → `v1446run.ps1` 等**补丁/探针脚本一律纯 ASCII**（注释也用英文），中文只留在 `.md` / `.js` / `.cjs` 里。

## 17. P1c 实施记录（v1449 · 来源归一：出建议 → 只写草稿 → 人工确认）

> 这是最初那件事的正解：**让老来源 / 校本卷名成型**。纪律是「**先出草稿再确认，绝不猜**」。

### 17.1 做了什么

**来源建议（`source_normalize.rs` 新增 `template_hint` + 4 个单测）**

套六类模板给一条**半成品建议**：只认得出类别 / 学段 / 学年，**缺的部分写「？」**。

- `2026届某市一模数学试题` → `2026 · 某市 · 模拟`（**直接成型**：年份与地区都从原串里机械抽出）
- `2027 届高三 8 月底学情调研` → `高三 · 8月底学情调研 · ？ · 2026-2027学年`（**学校名留「？」**，不猜）

**两个「指标诚信」修正（都是 v1449 探针查出来的）**

1. **`未知` 是哨兵值、不是来源**：原来 `is_canonical("未知")` 为真，于是一道**没填来源**的题会被算进「成型率」——
   正是 §12.3 警告过的「看着漂亮却毫无意义」。现在空串与 `未知` 都算「没有来源」：既拉低覆盖率、也不进成型分子。
2. **占位符不算成型**：`is_canonical` 增加 `is_placeholder()` 判定，「？」那段一律判为未成型 ——
   否则满屏「？」的建议也会被算进成型率。

**「归一」走草稿，而且是「更新」不是「新增」**

- 新命令 `lib_source_plan`（**只读**）：给每道题出建议 + 分类计数（alias / rule / template / none / 没来源）；
- 新命令 `lib_source_plan_apply`：把选中的建议生成**草稿**（`target_qid` 指向原题、`extra.patch` 只允许改 `paperName`），
  开一个 `sourceType = source_fix` 的批次，**幂等键**由这批 id 算出；
- `lib_import_commit` 新增**更新分支**：`target_qid > 0` 时按 `extra.patch` 把草稿字段合进**原题**的 meta，
  走同一个 `lib_prepare_qmeta` + `lib_sync_qcols`，并留 `reason = source_fix` 的修订快照 —— **正式库题数不变**。

**界面**：来源报告弹窗加「来源归一建议」区（五个计数 + 「现在 → 建议」明细 + 「生成 N 条归一草稿」）；
草稿箱那套确认 / 弃用 / 入库流程直接复用。
