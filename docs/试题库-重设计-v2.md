- 章节分布：解析几何 35 / 函数与导数 33 / 三角函数与向量 13 / 概率与统计 10 / 集合与逻辑 9 / 立体几何 5
- 题目字段（meta JSON）：stem / options / answer / solution / knowledge / difficulty / score / qtype / section / chapter / date / year / paperName / region / answerFrom

## 3. 新系统设计

### 3.1 一句话

> 左边一棵树（章节 / 知识点），中间一列题卡（题干摘要 + 题型 + 难度 + 年份/来源小标签），
> 右边预览（题干、选项、答案、解析、配图），底部两个动作：**插入幻灯片** / **加入试卷**。
> 顶部一条筛选栏（搜索 + 题型 + 难度 + 年份 + 只看未核对），筛选结果可以**一键成卷**。

### 3.2 数据模型（继续 SQLite，一次 v2 → v3 迁移）

沿用 library_item（type=question），**把要筛选的字段从 meta 抽成真列 + 建索引**：

    -- v3 迁移（幂等：先查 pragma_table_info，缺哪列加哪列）
    ALTER TABLE library_item ADD COLUMN qtype TEXT;      -- choice / blank / answer / proof
    ALTER TABLE library_item ADD COLUMN level  TEXT;     -- 基础 / 中档 / 拔高
    ALTER TABLE library_item ADD COLUMN difficulty INTEGER;
    ALTER TABLE library_item ADD COLUMN year   INTEGER;
    ALTER TABLE library_item ADD COLUMN source TEXT;     -- 试卷名
    CREATE INDEX IF NOT EXISTS ix_q_section ON library_item(type, section);
    CREATE INDEX IF NOT EXISTS ix_q_qtype   ON library_item(type, qtype);
    -- 知识点：多对多，单独一张表（一道题多个考点）
    CREATE TABLE IF NOT EXISTS question_kp (qid INTEGER, kp TEXT, PRIMARY KEY(qid, kp));
    CREATE INDEX IF NOT EXISTS ix_kp ON question_kp(kp);

- **答案可信度**：保留 answerFrom（空 = 原卷没有 / manual / auto / ai），列表上用不同颜色小标签区分 ✓
- **配图**：沿用现在的 assetId 方案（图片放 %APPDATA%\lj-mathslides\mineru\），题目只存 id ✓
- **迁移前照例备份**：lib_migrate 已有「先备份整个 .db，再逐版升级」的机制（v1435 做的 ✓），直接复用

### 3.3 分类体系（三层，先能落地再谈完整）

1. **必修板块**（11 个，沿用现在的口径）：集合与逻辑 / 函数与导数 / 三角函数与向量 / 数列 / 不等式 / 立体几何 / 解析几何 / 概率与统计 / 复数 / 计数原理 / 未分类
2. **知识点**（三级目录）：先**从已有 169 题里长出**常用考点（50 个左右，手工收一遍），
   将来再导入教材大纲（人教版/北师大版）替换 —— 不预先造 500 个用不上的节点 ✗
3. **题型 / 难度 / 年份 / 来源**：扁平标签，全部可筛选

### 3.4 导入入口（决策 ④：保留链路，界面重做）

一条流水线，四个可见的步骤（每一步都能人工改 ✓）：

    ① PDF → MinerU（或直接粘贴 Markdown）
    ② 正则切题 + 结构兜底（parseQuestions，选项救回 / 双栏 / 参考答案截断）
    ③ 人工校对表：左边原文块、右边切出来的题（可合并/拆分、改题型、补章节）
    ④ 入库：来源(年份+试卷名) 必填 · 按题干去重 · 写完给一份体检报告（空章节/0 选项/答案缺失 计数）

- 「AI 校正」保留为**可选按钮**（只对可疑题做增量，数量不符就不合并 —— 旧版验过的好规矩 ✓）
- 原卷没有的答案**留空**，不让模型自己解题（避免老师误信 ✗）；模型解出来的标 ai 并要求人工确认

### 3.5 组卷（选题·组卷 定位的核心动作）

- 按当前筛选/勾选 → 「生成试卷」：可设题量、按题型配比、按难度配比（旧版 blueprintOf 的做法重写）
- 生成结果**先给预览**（题号 / 分值 / 合计），再「插入试卷正文」（PaperModal 的 input）或「导出」
- 组卷结果里自动附**来源出处**（年份 + 试卷名），老师要能一眼看出题目来历 ✓

## 7. M1 完成记录（v1440 · 数据层 v3 迁移 + 旧题升级导入 + 体检报告）

### 7.1 做了什么（全在 Rust 侧，前端这轮没动）

- `LIB_SCHEMA_VERSION` 2 → 3；`lib_migrate` 增加 v2→v3 一步（**先备份再迁移**，幂等）

- `lib_save` / `lib_save_many` 保存后同步；`lib_remove` 连带清掉该题的知识点行

### 7.2 两个必须记住的坑（都已踩过并修）

1. **`library_item` 本来就有 `source` 列**（条目出处 / 内置标记那类用法）→ 试卷名**另开 `paper` 列**，不能直接照抄设计文档里的 `ADD COLUMN source` ✗
2. **分组统计里 INTEGER 列必须 `CAST(... AS TEXT)`** —— `year` 是 INTEGER，用 `String` 取值会整行失败，分组结果直接变成**空对象** ✗（实测抓到，已修）

## 8. M2 完成记录（v1441 · 新的只读题库窗口：左树 + 筛选 + 题卡 + 预览就地编辑）

### 8.1 做了什么

### 8.3 这轮踩到的两个坑（都要记住）

1. **`npm run build` 之后必须紧跟 `node clean-dist.cjs`** ✗ —— Tauri 窗口加载的是 `dist/app/index.html`（v1438 为解决「根级文件被打包漏掉」加的），而这份是 `clean-dist.cjs` **构建后**从 `dist/index.html` 复制过去的 ✓。只跑 `npm run build` 不跑它 → 入口还指着**上一版**的 `assets/index-<旧hash>.js`，于是「代码明明改了、应用里却没有」（这轮白查了一次 Tauri 打包 ✗）。
2. **受限沙箱下 WebView2 的 CDP 起不来** —— workspace-write 模式下起 exe，WebView2 的命名管道被拦住 → 调试端口不响应、node 连不上（实测「CDP 未就绪」）→ 真机探针必须在更宽的模式下跑 ✓。
