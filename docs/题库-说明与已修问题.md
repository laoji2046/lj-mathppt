## 一、两个入口，别走错（这就是之前"点了没反应"的根源）

| 从哪打开 | 能干什么 | 插题 |
|---|---|---|
| **文件 → 题库**（工具栏）| 录入 / 批量导入 / 编辑 / 删除 / 查重清理 / 导入导出 JSON | ✗ **按钮是灰的**，底部写明"这里只管理题库" |
| **PDF 生成 → 试题库** | 上面全部 + **把题插进试卷正文** | ✓ 单题 / 勾选多题 / 规则组卷 / 整套插入 |

原因：插入的目标是**试卷正文**，而工具栏那个入口背后没有正文 —— 以前按钮照样能点，
还弹"已送进 PDF 生成"，其实内容进了空气。现在直接禁用并给出提示。

## 二、本轮（v1394）修掉的问题

| 问题 | 症状 | 修法 |
|---|---|---|
| **假成功** | 从工具栏打开题库，点插入 → 弹"已送进 PDF 生成"，内容丢了 | 加 `manageOnly` 属性：该模式下插入按钮**禁用** + 底部提示；`blockIfManageOnly()` 兜底 |
| **回执串台** | 整套插入/组卷插入后提示"已插入试题 #0" | `insert` 事件多带一个 **label**（整套「…」共 N 道 / 规则组卷 N 道 / 已勾选 N 道），PDF 窗口按它回执 |
| **重复插入** | 同一批题连点两次 → 正文里灌两份 | 记住"这批插过"，再插同一批会**先确认**；勾选 ≥10 道时也先确认 |
| **整套插入无闸门** | 点一下就把整个"未归卷"散题全灌进正文 | 插入前确认「共 N 道 / 合计 M 分」；散题组旁边标 **⚠ 散题合集** |
| **两套卷子挤在同一页** | 连插两套 → 两套 1.2.3. 混在一起 | 整套/组卷插到**已有内容的正文**后面时，自动先插一个 `[分页]`（每套卷子各从新的一页、题号各从 1 起） |
| **JSON 往返丢字段** | 导出的题库再导入 → **试卷名 / 章节 / 分值 / 答案来源**没了（整套归组、章节筛选、卷面总分全错） | `parseQuestionsJson` 补齐 `paperName / chapter / scoreExplicit / yearExplicit / answerFrom`；`importParsedQuestions` 尊重存档里的答案来源 |
| **导出语义矛盾** | 筛选结果为空时，点"导出 JSON"**偷偷导了整个题库** | 改成一个按钮=**导出筛选结果**、一个=**导出全部**；筛选为空时明确提示 |
| **保存提示永远是"已存入"** | 改了题也说"已存入" | 先记住是不是编辑，再判断提示（并带上 #id） |
| **自动识别覆盖手填** | 粘贴正文后自动识别，把老师手填的年份/试卷名覆盖掉 | 只在**还没手填**时自动带入 |
| **死代码** | `diff`（1–5 难度精确筛选）没人写、`.qb__diff/.qb__d` 是死样式 | 删掉 |
| **表单缺"试卷名"** | 试卷名是整套归组的依据，事后没法手改 | 表单加「试卷名」输入框 |

## 五、用 PDF 试卷导入（MinerU，v1404 起）

**入口**：试题库工具条 →「**导入 PDF（MinerU）**」。

1. 在题库顶部把 **MinerU token** 填进去（[mineru.net/apiManage/token](https://mineru.net/apiManage/token) 免费申请，每日 2000 页）。
   - token 只存**本机**（localStorage），不进源码、不进 git。
   - **不填 token** 也能用，但只能走免登录的**轻量接口**（≤10MB / ≤20 页，只出 Markdown）——
     实测**公式会乱**（会插 `~` 占位符、把 `A` 变成 `\cal A`），**数学卷务必填 token**。
2. 点「导入 PDF（MinerU）」→ 选 PDF（电子版/扫描/拍照都行）→ 自动

## 六、题面 `[图N]` 与「插入当前幻灯片」（v1406 起）

- **`[图N]` 现在真的有图了**：从 PDF（MinerU）导入时，题干里的 `![](images/x.jpg)` 会自动变成 `[图N]`，
  并把对应的图**存进题里**；列表里带图的题会显示 **图N** 标记，详情面板有缩略图。
- 插到**试卷正文**时，整套题会**整批重新编号**（多道题各自的"图1"不会撞号），图片注册进试卷、预览/导出 PDF 都在。
- **插入当前幻灯片**（详情面板）：题干+选项作为一个**文本元素**，题里的图作为**图片元素**插进去；
  幻灯片不走 `[图N]` 那套约定，所以标记会去掉、直接插真图，图拖一下位置即可。
  勾「连答案/解析一起」会把答案与解析也写进同一个文本元素。
- 注意：**不填 token 走轻量接口时没有图片实体**，那些 `![](images/…)` 会原样留在题干（不编空号）。
- 已知隐患：图以 base64 存进题里，试卷草稿（localStorage `lj-paper-draft-v1`）体积会跟着变大，
  整卷几十张图可能触到 5MB 上限（有 try/catch 兜底不会崩，但草稿可能存不上）。
- 列表顺序：**新录入的在最上面**（`ORDER BY id DESC`，公式/图形/课件库同样如此）。
- 难度筛选：除了 易/中/难，还有 **难度值 1|2|3|4|5** 细筛，两者可叠加。

   **提交 → 上传 → 解析（显示 x/y 页）→ 下载 → 解压**，真卷实测 **7–10 秒**。
3. 识别完，Markdown **直接灌进「批量导入」面板**（不会自动入库）：
   面板会显示「识别到 N 道题…已跳过 M 行考生须知／抬头」，**你核对题干/选项后再点「识别并导入」**。
4. 产物同时落盘在提示里的「**产物目录**」：`full.md`、`<uuid>_content_list.json`、`images/*`
   —— 以后题面 `[图N]` 配图就从这里取。
5. 走的是 **Rust 侧 HTTP**（网页端直连 mineru.net 会被 CORS 挡），参数照官方文档 + 参考实现：
   `model_version: vlm`、**`is_ocr: true`（数学卷必须）**、上传 `PUT` **不带 Content-Type**（OSS 按空 Content-Type 签名）。

**踩过的坑（都不是 MinerU 的问题）**：① 前端 `importPdfToBatch` 先置 busy 再调 `runMineru`，
而后者开头"忙就返回" → 命令根本没发出去、界面永远停在「识别中…」且不报错（v1404 修）；
② reqwest+rustls 必须先 `install_default()` 装 CryptoProvider，否则第一次请求 panic（命令里 panic 不回前端）；
③ 用旧 exe 测（dist 没走 clean-dist 流程）会看到"没有按钮"的假象。

1. **题目里的图形不落库** ✗（价值最高）：题面可以写 `[图N]`，但图片只活在试卷草稿里 ——
   库里没存图，插到别的文档要么红字"图片缺失"、要么**静默指向同号的另一张图**。
   要做：`QuestionMeta` 加 `images`，存/取题时一起带图并在插入时重编号。
2. **列表没有分页/虚拟滚动**：几百道题全渲染；查重扫描是 O(n²) 且 >400 条时会静默跳过近重复（应至少报出来）。
3. **排序被"引用次数"打乱**：`lib_query` 按 `used_count DESC`，每次插入都累加 —— 但界面已经不显示引用次数、
   抽题也不按它排序，属于纯副作用（改成按 id 排序更符合直觉）。
4. **难度只有 易/中/难 三档**（库里其实是 1–5）；知识点与板块共用 tags 列，标签筛选会命中板块名。
5. **无测试**：`parseQuestions` / `useQuestionLibrary` 这类纯函数没有回归网（本轮的 JSON 往返是用临时 Node 探针验的）。
