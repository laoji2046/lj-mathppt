# 矢量描摹 · 诊断与调参记录

> 起因：用户给出三张对照图（原图 / 描摹输出 / 人工修正），反映两个毛病：
>   ① **漏边** —— 原图里 D 连着 A、E、C，输出里 D 近乎孤立（**D–E、A–E 丢了**）
>   ② **碎片** —— D 右下多出一簇编号 10–14 的短线（一条虚线的断续段被拆成多条）

## 算法流程（`src/composables/vectorize.ts`）

     二值化 → 细化(thin) → 建图(buildGraph) → Douglas-Peucker 简化
       → **共线短划合并成虚线** → 顶点归并 → 解消十字交叉 → 交点精修

## 关键发现：作者早已针对这两条边反复调过

源码 407–424 行的注释**逐条点名了用户丢的边**：

- 短划（十几像素）的主轴方向估计有噪声，10° 的对齐门槛会把同一条虚线上的短划拆开；
  拆散之后每堆不足 2 个就会被当字母抹掉 —— **整条虚线随之消失**
- 4px 太严：虚线本身画得略有抖动，**实测 A–E 那条线上各短块相对理想线偏了 2~12px**，
  一超限就被拆成孤立小块、凑不满 3 个 → 当字母抹掉 → **整条边消失**  ← **A–E 被点名**
- ≥2 就算虚线：**只有两截的短虚线**（例如 **D–E、C–F** 那种）天生凑不满 3  ← **D–E 被点名**

**所以不是没想到，而是这一张图的抖动超出了当时调参样本的范围。**

## 本轮的改动（v2026.09.1365）

**元凶**：第 413 行写死的「到理想直线的垂距」门槛 `> 7` —— 而注释自己说实测偏 2~12px，
12 > 7 必然把 A–E 的短划拆断。

改法：

```diff
- if (Math.abs(vx * -A.uy + vy * A.ux) > 7) continue      // 到 A 所在直线的垂距
+ if (Math.abs(vx * -A.uy + vy * A.ux) > (opt.dashPerp ?? 12)) continue
```

同时把它提为**可调参数** `VectorizeOpt.dashPerp`（默认 12）—— 默认值即可调、可回退。

## v1367：三道杂点门槛（治"多出来的线段"）

用户反馈：**"多了一些可删掉又不影响其他的线段，由一些杂点导致的"**。

⚠ **必须说清楚：这个毛病我没能复现。** 手上三张样本图分别跑 v1365 / v1366 两套参数，
输出**逐条边完全一致**（19 条，长度一模一样）。`1-原图.png` 里最小的连通域是 6.4px，
且 7.3px 重复出现十几次 —— 那是真实虚线的短划，**不是杂点**。所以用户看到的线段来自另一张我没有的图。

不过"杂点凑成线段"的机制在代码里确实存在，而且和用户的每一句描述都对得上（无害、独立、可删）：

1. `stripText` 把 **≥2 个小连通域** 判成"一条虚线的短划"（源码 439 行注释：`≥2 就算虚线`）
   → 两个杂点 = 一条假虚线 → 凭空多出一条线段；
2. 只有 **1 个** 小块会被当字母抹掉，所以**单个**杂点本来就是安全的；
3. 小连通域之外的**大**墨团若被细化成短路径，会走 `leftover` 分支（815 行），
   变成一条**不吸附**的孤立虚线段 —— 悬在图形里，删掉不影响任何别的边。

据此加三道**只做减法**的门槛（均为 `VectorizeOpt` 字段，默认值生效）：

| 参数 | 默认 | 作用 |
|---|---|---|
| `dashMinPiece` | 4px | 主轴长度 < 4px 的小块直接当噪点抹掉（真实短划十几像素，差一个数量级） |
| `dashMinTotal` | 16px | 一堆短划**总长度**不足 16px 就整堆抹掉（两个 7px 杂点 = 14px → 抹掉） |
| `dashMinEdge` | 80px | 虚线边**两头都没吸附到图形顶点**、且短于 80px → 整条丢掉（孤立的杂点段） |

外加一处收紧：**虚线链的吸附半径不得超过链自身跨度**（原来固定 `snapDash = 60`）。
几个杂点凑出的短链跨度只有十几像素，却拿着 60px 半径去够远处的顶点，于是凭空多出一条横跨图形的线段。
跨度 ≥ 60px 的链行为完全不变。

## v1369：把「图清理」收尾放到所有改动图的步骤之后

用户给了两张图（描摹后 / 人工修正后）并点名：**点11 多余、点10 位置错、点9 和点3 不该有**；
补充说明：**点9 连着两条线段**（度 2）、**点3 是一个假交点**。

⚠ 本轮识图配额耗尽，**我没能亲眼核对那两张图**；而且两张都是**输出**，我没有生成它们的**原图**，
所以无法复现、也无法验收。下面是从"度 2 直线顶点 / 假交点"这两条描述 + 代码顺序推出来的**确定缺陷**。

### 缺陷：一次性清理跑在了会改动图形态的步骤**之前**

`vectorizeFromInk` 末尾的顺序是：

```
extendDashed() → collinearSimplify() → contractShort() → mergeVerts() → dropIsolated() → dedupe()
→ refineCorners()   ← 会挪顶点
→ mergeVerts()      ← 作者只记得补这一句
```

- `dissolveCrossings`（解十字交叉）只在 **`extendDashed` 之前**跑过 —— 而 `extendDashed` 会把虚线端点
  **改指到另一个顶点**上；那个新接头若落在一条直线上就形成**假交点（度 4）**，此前再没人复核它 → **点3**。
- `collinearSimplify`（度 2 且共线 = 直线上的假顶点）只在 **`refineCorners` 之前**跑过 —— 而精修会挪顶点，
  **挪完才变共线**的假顶点就活到了最后 → **点9**。

1235 行的注释写着"精修会把顶点挪位置，挪完必须再合并一次"，说明作者知道这类顺序陷阱，只是漏了这两个。

### 改动

1. 把解十字交叉提成可重复调用的 `dissolveCrossings()`，并在 `refineCorners()` 之后与
   `collinearSimplify()` 一起**再跑一遍**。
2. 新增 `VectorizeOpt.collinearCos`（默认 0.995 ≈ 5.7°）—— 点9 那种直线上的微小折角正是被这个阈值卡住的；
   手绘/扫描件可放宽到 0.99（8°）或 0.98（11°）。
3. 修掉 `nearestOn` 失效的 `sgn` —— 原来符号被 `Math.abs` 吃掉，方向约束等于没有，
   链端点可能吸到**链自身跨度内部**（或同一个）顶点。**基线（原图/人工修正）上零影响**。

### 试过但**回退**了

给 `findAlong`（虚线端点外延吸附）加垂距约束（`extendPerp = 14`）：25° 夹角在 72px 射程上等于允许 ±30px
横向偏移，看起来正是"端点被拽到旁边那条线的顶点上"。**实测是回归**：

| 样本 | 加之前 | 加之后 |
|---|---|---|
| `1-原图.png` | 18 条（…89D…）| 17 条，**89D → 21D**（虚线边被截短）|
| `3-人工修正.png` | 21 条，虚线 10 条 | 19 条，**虚线只剩 9 条**（丢了一条虚线边）|

原因就在源码 807 行的注释里：短划链的**方向估计本身有噪声**，真端点确实会偏离拟合直线，
只给 14px 垂距就吸不上去了。**这个方向不能这么修。**

## v1373：插入试卷 / PDF 的图形没有顶点字母（出口分叉）

用户报：**「插入 pdf 生成没字母，插入幻灯片页面可以显示顶点字母」**。

根因就写在 `VectorizeDialog.buildSinkSvg()` 自己的注释里：
> 只画边（虚实用 stroke-dasharray）—— **顶点圆点和字母标注暂不带**，但线稿的几何信息是完整的。

同一个描摹结果有**两条完全不同的出口**：

| 出口 | 走的路 | 结果 |
|---|---|---|
| 幻灯片 | `buildPatch()` → mathfig **活元素** → `MathFigureElement.vue`（带 vlabels） | 有字母 ✓ |
| 试卷 / PDF生成 | `buildSinkSvg()` 手拼一段"**只有 `<line>`**"的 SVG → `PaperModal.svgStringToPng` 栅格化成 `[图N]` | **没字母，连顶点圆点也没有** ✗ |

这正是 v1229 的老毛病（"两份实现迟早漂移"，见 `figureRender.ts` 头注释）—— 只是这次漏的是试卷出口。

### 改法

`buildSinkSvg()` 改成**跟画布同一套渲染**：`buildPatch()` → `renderFigureSvg()`（挂真组件取它的 `<svg>`）→
点、线、虚实、字母一次全给。旧的只画边版本**保留为兜底**（真组件挂载失败时至少还有线稿）。

一个必须处理的细节：组件给的 `<svg>` 带 `width/height="100%"`，而试卷侧 `svgStringToPng` 还会再插一对
width/height —— XML 里**重复属性直接解析失败**（表现为"图形转图片失败"）。所以出口前把那两个属性摘掉。

### 端到端验证（`.probe/vpaper.cjs`，跑在打包后的 exe 上）

程序化生成的 file input 会弹**原生**对话框、CDP 抓不到；所以探针里**劫持 `HTMLInputElement.click`** 把它拦下来，
再劫持 `encodeURIComponent` 抓住**真正送去栅格化的那段 SVG**：

| 检查项 | v1372（改前） | v1373（改后） |
|---|---|---|
| 试卷侧 SVG 里的 `<text>` 个数 | **0** | **7** — `B,F,C,A,B,R,D` |
| viewBox | — | `0 0 440 410` ✓ |
| svg 首标签 | — | `width="1200" height="1118" … viewBox=…`（无重复属性 ✓）|

⚠ 顶点圆点仍是 0：`MathFigureElement` 只在 `showDots === true` 时画圆点，而描摹元素没开这个开关 ——
**幻灯片和试卷现在是一致的**（都没有点）。要加点属于单独一件事。
