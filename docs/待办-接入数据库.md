# 待办 · 应用接入数据库

> 记录时间：2026-09-16 深夜 · 用户提问「咱们的应用能不能接入数据库」
> 状态：**已给出评估，等用户回答动机（a/b/c/d）后才定方案**

## 结论

**能做** ✓。但「接入数据库」有四条完全不同的路，选哪条取决于动机。

## 已核对的现状（读代码得到）

**前端持久化：全部是 localStorage**

| 键 | 存什么 |
|---|---|
| `lj-mathslides-vue:deck` | **整个演示（用户的全部内容）** |
| `lj-mathslides-vue:versions` | 版本历史 / 快照（**会持续膨胀**）|
| `lj-mathslides-vue:addons` | 插件开关 |
| `lj-mathslides-vue:formula-presets` | 公式预设 |
| `lj-mathslides-vue:newdeck-wizard` | 向导开关 |
| `lj-paper-draft-v1` | 试卷草稿（实测 230 KB）|

**Rust 侧：10 个手写 `#[tauri::command]`**（lib.rs）

    app_dir · list_dir · export_json · images_dir · read_local_image · set_capture_mode …
    前端经 `composables/useTauri.ts` → invoke 调用

**Tauri 插件：一个都没装** —— 没有 tauri-plugin-sql / fs / dialog，全靠手写命令。

    Cargo 依赖：tauri · serde · serde_json · base64 · xcap · image

## 关键判断

**localStorage 上限约 5~10 MB**，而 `:deck` + `:versions` 会持续膨胀。
（已知：试卷草稿 230 KB；图片以 dataURL 存进 deck 会成倍放大。）
→ **其实已经踩到天花板了**，用户此时提出这件事，时机是对的。

## 四条路

| 路 | 解决什么 | 代价 |
|---|---|---|
| ① **SQLite 本地库** | 存不下 / 怕丢 / 版本历史膨胀 | Rust 加 rusqlite；exe 约 +1~2 MB；**要写数据迁移** |
| ② **tauri-plugin-store** | 只把 localStorage 换成磁盘文件 | 最小；无 SQL；几乎不动架构 |
| ③ **远程库**（MySQL/Postgres/Supabase）| 多设备 / 多人共享 | 要后端 + 账号；**破坏离线单机身份**；要处理冲突 |
| ④ **题库/素材结构化检索** | 标签查询 / 组卷 / 复用 | ① 就够，不必上远程 |

## 推荐

    a) 存不下/怕丢        → ②（最省）或 ①（最彻底）
    b) 多设备/多人共享    → ③ —— **但这是改产品，不是加功能**；先定账号与冲突策略
    c) 题库检索           → ① 本地即可

## ⚠ 三件必须提前知道的风险

1. **体积**：rusqlite 约 +1~2 MB。刚把 exe 从 39.92 压到 29.08 MB。
   → 做完必须**复测 exe 体积与启动时间**。

2. **迁移（最容易出事）**：用户内容全在 localStorage 的 `:deck` 里。
   换库时若不写迁移 → **用户打开发现内容全没了**。
   → 必须：首次启动自动把 localStorage 数据导进库，且保留回滚路径。

3. **离线身份**：走远程库就不再是纯本地离线应用。
   联网失败降级、同步冲突、隐私（教案/试卷是个人成果）都要交代。
