## 三个直接可借的技术

### ① 公式边界修复（**已借，v1426**）
`fixFormulaBoundary()`：MinerU 常把紧跟公式的选项标签**吸进 `$...$`**：
```
$|z| = A.1$        ← 错：A 选项的 "1" 被并进公式
$|z| =$ A.1        ← 对：把闭 $ 挪到选项标记前面，后面照常切
```
规则：`$…` 里的内容**以「空白 + A-D + .／．／、」结尾** → 把 `$` 提前 ✓（我们已按此实现并测试 ✓）

### ② 最长有序选项序列（**已借，v1426**）
`longestOrderedRun()`：题干里常有"如图 **B.** 为线段 AC 的中点"这种**杂字母**，
老写法"见到标记就切"会被带偏 ✗；参考实现只保留**最长的 A→B→C→D 有序序列** ✓
（我们已借：一道含"B 为…"的题现在稳定切出 4 个选项 ✓）

### ③ 用 content_list 的**块 + bbox 间距**切题（**推荐下一步**）
参考实现**根本不解析 full.md** ✗，而是：
- 吃 `content_list.json` 的**元素数组**（每个元素有 `type` / `text` / `bbox` ✓）
- 用 `bbox` 的**垂直间距**判断"新块 vs 上一题的续行"（`examParser.ts` 里 `GAP` 那条规则 ✓）
- 于是：**表格**（`type: 'table'`）、**公式**（`equation`）、**图**（`image` + bbox）、
  **页眉页脚/页码**（`header/footer/page_number` → 直接排除 ✓）都是**结构化的**，不靠正则猜 ✓

# 第二份参考：MathBank（JudgePeach/math-question-bank）

用户给的仓库：**MathBank —— 本地化数学题库与组卷排版工作台**（Python + 本地运行，228 个文件，
成熟度远高于我们这一块）。先把它“怎么做的”看明白，再决定借什么。

## 它的整体设计（值得学的四点）
1. **PDF 拆解是“双策略 + 页级置信度路由”**（不是死磕一种解析）：
   `Inspector 属性探测 → 页级置信度 → 高置信走原生矢量文本/公式直提(0 视觉 Token) / 低置信降级 VLM 视觉 OCR → 跨页缝合 → LLM 结构化切片` ✓
   → **思路**：解析质量要**先自检再决定走哪条路**，而不是“解析完就丢给老师”。
2. **用 LLM 做“结构化切片拆题”**，正则只做预处理 ✓（我们目前全靠正则 ✗ —— 这是差距最大的一点）。
3. **教材大纲可切换**：内置人教A/人教B/苏教/沪教四套**三级目录**（模块 → 章 → 节，如 `必修一/1. 集合与常用逻辑用语/1.1 集合的概念`）✓，
   切换大纲时**自动映射**已整理好的题目 ✓ —— 正好治我们的“板块/章节”只有一层的短板 ✓。
4. **工程化配套**：`db_migrations.py`（库结构迁移 ✓ 我们没有）、`health.py`（健康检查 ✓ 我们刚加）、
   `question_duplicate_service.py`（查重服务化 ✓）、`content_locks.py`（并发写锁 ✓）、`backup.py`（备份 ✓ 我们有）。

## 我们这一轮实际借了什么（可验证）
**导入质量自检提示**（借它“置信度路由 → 给人一句可操作结论”的思路 ✓）：
批量导入面板现在会直接说清楚这批题哪里要人管，例如：
```
识别到 19 道题 —— 19 道里 3 道需要核对（选项不全 / 没答案 / 题干过短）；
入库后点「只看待核对」逐题处理；若是整卷选项都缺，换「全图 OCR」重跑一次更稳
```
（之前只含糊写“其中 N 道没识别到答案” ✗ —— 现在结论 + 下一步动作都有 ✓）

## 结论：我们的差距与优先级
| 差距 | 优先级 | 说明 |
|---|---|---|
| **走 content_list（块+bbox）而不是纯文本 MD** | ★★★ | 前面 v1425 接线失败就栽在这 ✗；参考实现根本不解析 MD ✓ |
| **LLM 结构化切片** | ★★ | 正则治不了的（跨栏、公式被吃、答案混排），LLM 一次就能结构化 ✓ |
| **三级教材目录**（模块/章节/小节）| ★★ | 我们只有 10 个扁平板块 ✗；目录数据要**自己整理**（AGPL ✗ 不能抄）|
| 库结构迁移 / 并发锁 | ★ | 现在规模小，先记账 |


这对我们尤其重要：我们这次"选项救回"失败，根因正是**拿整篇纯文本去字符串匹配** ✗；
换成块 + 顺序/间距定位就稳了 ✓（这也解释了为什么参考实现不需要"救回"这种补丁）
