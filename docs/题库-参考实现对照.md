## 三个直接可借的技术

### ① 公式边界修复（**已借，v1426**）
`fixFormulaBoundary()`：MinerU 常把紧跟公式的选项标签**吸进 `$...$`**：
```
$|z| = A.1$        ← 错：A 选项的 "1" 被并进公式
$|z| =$ A.1        ← 对：把闭 $ 挪到选项标记前面，后面照常切
```
规则：`$…` 里的内容**以「空白 + A-D + .／．／、」结尾** → 把 `$` 提前 ✓（我们已按此实现并测试 ✓）

### ② 最长有序选项序列（**已借，v1426**）
`longestOrderedRun()`：题干里常有"如图 **B.** 为线段 AC 的中点"这种**杂字母**，
老写法"见到标记就切"会被带偏 ✗；参考实现只保留**最长的 A→B→C→D 有序序列** ✓
（我们已借：一道含"B 为…"的题现在稳定切出 4 个选项 ✓）

### ③ 用 content_list 的**块 + bbox 间距**切题（**推荐下一步**）
参考实现**根本不解析 full.md** ✗，而是：
- 吃 `content_list.json` 的**元素数组**（每个元素有 `type` / `text` / `bbox` ✓）
- 用 `bbox` 的**垂直间距**判断"新块 vs 上一题的续行"（`examParser.ts` 里 `GAP` 那条规则 ✓）
- 于是：**表格**（`type: 'table'`）、**公式**（`equation`）、**图**（`image` + bbox）、
  **页眉页脚/页码**（`header/footer/page_number` → 直接排除 ✓）都是**结构化的**，不靠正则猜 ✓

这对我们尤其重要：我们这次"选项救回"失败，根因正是**拿整篇纯文本去字符串匹配** ✗；
换成块 + 顺序/间距定位就稳了 ✓（这也解释了为什么参考实现不需要"救回"这种补丁）
